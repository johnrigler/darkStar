# Dark Star — John Evidence Gallery — 2026-10-03

This note translates the John / Mogwai provenance idea into a concrete editorial and interface pattern.

## Purpose

John should increasingly replace retrospective explanation with inspectable artifacts.

The reader should be able to move from:

claim
-> artifact
-> conventional explorer-style view
-> annotated interpretation
-> related artifacts

The goal is not to make Mogwai authoritative.

The goal is to make Mogwai a readable index into evidence that can also be recovered independently.

## Evidence card

Each historical object should be representable as an evidence card containing, where available:

- short human title;
- chain;
- transaction ID or address;
- block / timestamp information;
- raw value or script data;
- ordinary explorer-style rendering;
- Chisel-aware highlighted rendering;
- natural-language interpretation;
- provenance notes;
- related transactions or addresses;
- direct recovery information;
- uncertainty / interpretation note.

Observed facts and interpretation should be visually separated.

## Views

A reader should be able to switch between several views of the same object.

### Raw

Show the underlying machine data with minimal interpretation.

### Explorer

Render the transaction in a familiar block-explorer information layout.

This should be clearly labeled as a Mogwai reconstruction, not as the actual interface of Blockchair or another third-party explorer.

### Annotated

Highlight portions that become meaningful under the Chisel / address-language reading.

Possible annotations include:

- readable characters;
- address-language prefix;
- delimiters;
- padding;
- checksum;
- numeric values;
- repeated structures;
- input / output relationships;
- apparent conversational markers.

### Readable

Show the best current human reading of the artifact.

Do not hide ambiguity.

If several interpretations are plausible, show that explicitly.

### Provenance

Show how the object relates to earlier and later artifacts.

The provenance view is where John becomes a history rather than a collection of isolated curiosities.

## The college sequence

The repeated outreach / testing transactions should eventually be presented as a sequence rather than as isolated examples.

The reader should be able to see:

test 1
-> institutional name
-> transaction
-> technical variation

test 2
-> another institution
-> transaction
-> technical variation

test 3
-> another institution
-> transaction
-> technical variation

and so on.

This lets the ledger display both the social gesture and the engineering iteration.

The absence of visible response is part of the artifact history.

The humor should not be removed by explanation.

The reader should be allowed to notice that John keeps addressing institutions that may never have known they were being addressed.

## The greeting sequence

Where the Dogecoin greeting appears in actual artifacts, preserve the repetitive calling-card form.

Dear [name].
Hello.
How are you?
I'm doing well.
Thanks for asking.
Anywho...

The evidence gallery should make it possible to compare several instances side by side.

The repetition itself is meaningful.

It shows the greeting becoming ritual, mask, and signature.

## Numeric language

39692 and related numeric forms should be presented alongside the human-readable address system rather than buried as an earlier obsolete experiment.

John should make clear that there are multiple linguistic surfaces available through inexpensive cryptocurrency mechanisms.

The important historical point is that the numeric interaction can exist without Chisel.

Chisel is a later interpretive and construction layer, not the origin of every underlying idea.

## External readability

Every evidence card should include enough information that a reader can leave Mogwai and verify the artifact elsewhere.

The ideal path is:

Mogwai interpretation
-> transaction / address identifier
-> independent explorer or node
-> same underlying object

This is essential to the credibility of the project.

## Historical uncertainty

John should preserve uncertainty rather than smoothing it away.

For each artifact, distinguish:

- directly observable;
- mechanically decoded;
- historically documented;
- inferred;
- speculative.

This lets Dark Star remain strange without turning ambiguity into false certainty.

## Editorial role

The evidence gallery should begin appearing before John in small doses.

In the Preface and Matthew, a single object may be shown with only one or two views.

By Luke, the reader can encounter raw / annotated / readable transformations.

By John, the full evidence-card grammar should be available.

This creates a learning curve rather than a sudden technical appendix.

## Final principle

The strongest John pages should feel less like:

"Here is what happened."

and more like:

"Here is the thing that happened. Look at it."
