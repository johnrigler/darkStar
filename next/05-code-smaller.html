Code smaller. Escape the stack.

Useful tools can harden into a measuring stick. A framework solves a real problem, then becomes a standard, then a curriculum, then a job category, then an investor's picture of what a serious project should look like.

tool
→ standard
→ stack
→ specialists
→ metrics
→ funding
→ stronger standard

Dark Star calls this stack capture: the tools used to implement ideas begin deciding which ideas are easy for the community to recognize.

The result is strange. Removing a token, server, framework, API, account database, or smart contract can make a system technically simpler while making it socially harder to explain.

Chisel therefore asks before adding a layer:

What property requires this?
Does the old constraint still exist?
Can the browser do it?
Can the protocol do it?
Can the user own the state?
Can the service be replaced?

This is not anti-React, anti-Node, anti-EVM, or anti-standard. Those tools solve real problems. The target is inherited necessity.

The aim is recoverability and legibility: code and artifacts that remain understandable after the original framework, server, provider, team, or conversation disappears.
