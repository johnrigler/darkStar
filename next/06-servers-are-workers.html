Servers are workers

A service does not need to be permanent merely because the identity or artifact it handles is important.

A server can be more like a miner, block explorer, RPC provider, indexer, hydrator, search engine, game host, cache, gateway, or relay.

It performs work. It may be paid for that work. It may disappear. Another provider may replace it.

This is acceptable when the durable state does not live exclusively inside the provider.

identity  -> cryptographic control
content   -> durable/content-addressed object
service   -> replaceable worker
payment   -> compensation for useful work
trust     -> verification + explicit assumptions

This is institutional decomposability. Identity can persist while the host changes. Content can persist while the index changes. Verification can persist while the interface changes.

The server is not the cathedral.

It is a worker.
